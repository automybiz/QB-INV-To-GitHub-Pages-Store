2. Why You Don't Need to Create a New MCP in GHL ▼

Look at how the Model Context Protocol (MCP) works under the hood:

  • How GHL Discovers Tools:
    1. When GHL connects to your Cloudflare Worker URL, it requests tools/list.
    2. Currently, your worker tells GHL: "I have 2 tools: turn14_search_items and turn14_get_pricing_and_stock."
    3. If you add a 3rd tool, partstech_search_parts, to your existing worker's script, GHL Ask AI will automatically discover and display it under your connected tools!
    4. You avoid having to click "+ Add custom MCP", paste URLs, enter accounts, and satisfy PKCE (S256) all over again!
3. How to Wire PartsTech Into Your Existing Worker ▼

Integrating PartsTech into your Cloudflare Worker takes two quick steps:

  1. Step 1: Save PartsTech API Keys in Cloudflare Secrets:
    • Go to your mcp-turn14 worker in Cloudflare → Settings > Variables and Secrets.
    • Click Add and store your PartsTech credentials:
      • PARTSTECH_API_KEY → (paste your PartsTech API Key)
      • PARTSTECH_USER_ID → (your PartsTech username/account ID if required by your tier)
  2. Step 2: Add the `partstech_search_parts` Tool Definition:
    • In your worker's tools/list, add: 
      {
  name: "partstech_search_parts",
  description: "Search PartsTech unified network across Worldpac, SSF, NAPA, and local dealers by vehicle and part name.",
  inputSchema: {
    type: "object",
    properties: {
      search_query: { type: "string", description: "Part name e.g. 'Water Pump'" },
      year: { type: "string", description: "Vehicle Year e.g. '2024'" },
      make: { type: "string", description: "Vehicle Make e.g. 'Porsche'" },
      model: { type: "string", description: "Vehicle Model e.g. '911'" },
      vin: { type: "string", description: "Optional VIN number" }
    },
    required: ["search_query", "year", "make", "model"]
  }
}
